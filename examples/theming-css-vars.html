StarGantt v2 — theming with CSS variables

CSS custom properties (CSS variables) control every painted colour, the canvas fonts and the bar geometry. Click the theme buttons to change the chart element's class, and watch the new look apply through CSS inheritance: the view plugin's theme module reads the --sg-* variables via getComputedStyle, invalidates the renderer and forces a repaint. Each theme also pins the chart's colour scheme through ThemeService.setColorScheme(), so the tokens it chooses not to override resolve on the matching half of the library's light-dark() defaults instead of following the OS into a mixed palette. System default overrides nothing at all and follows the OS.

Theme presets (runtime switching)

The buttons above swap CSS classes; these buttons call ThemeService.setPreset(name) instead. The list comes from presets() — the two bundled high-contrast palettes plus the Blueprint palette this page supplies through ThemeConfig.presets. An applied preset writes its tokens as inline custom properties on the chart element, so it deliberately wins over the page's own CSS blocks; None removes them again and hands control back to the theme buttons above.

Palette audit

ThemeService.audit() measures the palette actually in force — page CSS, scheme pin and any applied preset together — against the contrast floors this project audits its own defaults to: 4.5:1 for text, 3:1 for non-text UI marks, plus the row-state ordering (plain < stripe < hover < selected). A pair whose tokens cannot be read as colours is left out rather than reported as passing. theme.tokens lists what a self-contained palette has to cover.
