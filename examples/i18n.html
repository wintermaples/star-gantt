StarGantt v2 — internationalization (i18n)

What's on this page

One dictionary (createDictionary()), shared by treeGrid, taskBars, undoRedo and the merged interaction plugin's side panel / edit dialog / context menu / zoom toolbar, plus the runtime stargantt.i18n service for live lookups. The chart itself does not re-translate live: every plugin resolves its catalog once at setup, so a language change re-creates the chart (the buttons below do this).

    What to look for

    • One dictionary, many plugins: the grid headers, the detail pane on the right, the zoom toolbar in the chart's corner and the right-click menu all read their text from the same inline translation table via catalog().
    • Regional overrides: ja-JP only defines three keys; everything else resolves through the shortened prefix ja, then through en.
    • Partial dictionaries degrade cleanly: fr translates three grid headers and nothing else, so the rest of the chart stays on its built-in English defaults.
    • Wording vs. formatting: the dictionary only carries wording. The language buttons also set GanttOptions.locale, which the timeline header uses for its Intl month and day labels; the grid's built-in date columns stay locale-neutral ISO by contract, so this page passes its own Intl.DateTimeFormat through formatDate to localize them.
    • Builders are host code: a dictionary can only carry strings, so the pane's composed lines — the "← task (FS)" dependencies, the "name × units" assignments, the "n tasks selected" summary — come from functions supplied next to the catalog, where word order and pluralization belong.
    • Announcements too: undo/redo speaks its outcome through the focus service using the translated undoRedo catalog.
    • Task names are your data: the dictionary translates chart chrome, not the rows — localizing task text is the host's job.
