# Plugin: a11y (`stargantt.a11y`)

Package: `@stargantt/plugin-a11y` — Layer 5.
Status: normative.

## Purpose

Parallel ARIA DOM (`role="treegrid"` mirror, generated for the visible range only), roving tabindex, the `keys/bindings` point and its document-level dispatcher, keyboard focus + focus visualization (canvas box, grid-row outline, pane ring), aria-live announcements, keyboard multi-selection chords, shortcut help dialog, screen-reader summary table, keyboard zoom.

## Service

### `stargantt.focus` → `FocusService`

Store-shaped. The store is set only on an **effective** placement — a keyboard move, a pointer-follow, or a `focus(id)` call that changed the focused task; the initial row-0 tabindex fallback is not a placement and sets nothing.

```ts
export interface FocusState {
  /** The focused task, or undefined when no row holds the focus. */
  readonly focused: TaskId | undefined;
}

export interface FocusService {
  readonly state: Store<FocusState>;
  /** Places the roving focus on the task's row. Ignored for an unknown id and
   *  for a hidden (zero-height) row, exactly like an unknown id.
   *  Scrolls the row fully into view by the minimum amount. */
  focus(id: TaskId): void;
  /** Writes the message to the polite aria-live region. Known
   *  limitation: identical consecutive messages are not re-announced (the region
   *  speaks on content change); callers vary the text if every occurrence
   *  must be spoken. */
  announce(message: string): void;
}
```

Design note: `FocusState` carries the focused task only — there is no cell concept, because the mirror is one gridcell per row (see Mirror generation rules).

## Extension points

### Defined: `keys/bindings` (collect, last-wins)

```ts
export interface KeyBinding {
  key: string;
  run(): void;
  /** Shown beside the chord in the shortcut-help dialog; undescribed bindings
   *  work but are not listed. Contributor-owned prose, not catalog text. */
  description?: string;
  /** Evaluated at dispatch time after the chord matches; false skips, absent
   *  = always active; a throwing when() is guarded (core/pluginError, treated
   *  as false). */
  when?(): boolean;
}
```

Dispatch rules (all normative):

- **Last-wins:** of all contributions naming the same canonical chord, only the last registered runs; official defaults go through the point like anybody else's, so any of them can be replaced.
- **Chord syntax:** `Modifier+…+Key`; modifiers `Ctrl` (alias `Control`), `Alt`, `Shift`, `Meta` matched against the corresponding `KeyboardEvent` flags; order- and case-insensitive; a trailing `+` is the `+` key; single-character keys compare case-insensitively; a punctuation key the layout produces with Shift ignores the Shift state unless the binding names `Shift` explicitly; unknown modifier or missing key → the binding never matches.
- **Input guard:** no binding runs while the focus is on an `input`, a `textarea`, or inside a `contenteditable` region.
- **Claimed-stroke guard:** a keydown arriving with `defaultPrevented` set runs no binding (the context menu's roving keys are the shipped case).
- **Header guard:** no binding runs while the focus is on a grid `columnheader` or inside the grid header container (the header's own sort/resize keys win).
- The dispatcher calls `preventDefault()` on every chord a binding claims.

### Contributed

| Target | Contribution | Order |
|---|---|---|

## Commands

None.

## Events

Emits none of its own; focus state is observed via store subscription on `FocusService`. Consumes the input presses `grid/rowPointerDown` and the bar-press event (`pointer/barDown`) for focus-follows-pointer, and `view/scrolled` for the mirror window rebuild.

## Behavior

### Mirror generation rules

- A parallel `role="treegrid"` DOM in `.sg-a11y`, **virtualized identically to the canvas**: only the visible range plus buffer is materialized. The window's anchor is normative too: the mirror rebuilds its row window from `view/scrolled` — the same visible-range computation the panes use — so it always holds the rows on screen; the focused row is kept inside the window as an **additional** constraint when off screen, never as the sole anchor (a wheel scroll moves the window while the focus stays put).
- `aria-rowcount` on the grid and `aria-rowindex` per row give true positions; per-row `aria-level` and `aria-expanded` reflect the outline; the row's accessible text is the `rowText` catalog member built from name/period/progress read from the `data` service (the row model exposes no task fields).
- **One gridcell per row:** each mirrored row is a single `gridcell`; no per-column cells, no `columnheader` row, no `aria-colcount`/`aria-colindex`. Sort state reaches AT through `aria-sort` on the visible header cells (tree-grid's), not the mirror.
- **Hidden rows:** a row whose height resolves to 0 (the filter's `rows/height` hiding) is excluded from the mirror entirely — no element, not counted in `aria-rowcount`, `aria-rowindex` numbers only reachable rows. The roving focus skips hidden rows in every movement; a Shift range spanning them selects only reachable ones; `focus(id)` on a hidden row is ignored; a focused row that becomes hidden is relocated on the next rebuild like a removed row. The reachable sequence is derived from the row model's heights, re-derived when the row set or the data changes (the `rows` and `data` store subscriptions), cached in between.
- **Roving tabindex:** exactly one mirror row is tabbable; arrows move the focus. `aria-multiselectable="true"` is set on the treegrid exactly while the optionally resolved `SelectionService.mode()` reports `"multi"`; with no resolvable service the attribute is never set (see Dependencies — degradation).
- **`aria-selected` mirroring:** once selection information exists — a selection service is composed and resolved — EVERY mirrored row carries an explicit `aria-selected`: `"true"` while its task is in the current selection, `"false"` otherwise (the APG multiselectable-treegrid pattern). The attribute-absent state occurs only when no selection information exists at all (see Dependencies — degradation). Driven by the optional/late `SelectionService.state` subscription and reapplied on every mirror materialization, so pooled/reused row elements are always correct. The same subscription is what resets the keyboard anchor on selection changes this plugin did not itself cause.
- **Dependency read-out (`describeDependencies`):** each materialized row with links gains `aria-describedby` to a hidden description node (`rowDependencies` wording; predecessor/successor names from the store's link index in link order; unknown linked tasks dropped; both-empty rows carry no `aria-describedby`). Description nodes live in a dedicated visually-hidden `.sg-a11y-desc` container (items `sg-a11y-desc-item`), never inside the treegrid rows; ids unique per document. Rewritten on the same schedule as row text. Off by default; disabled output is byte-identical to no feature.
- **Slot pool:** released mirror row elements are parked in a per-mirror pool capped at 32 and reused; every attribute and text is rewritten on materialization — no observable ARIA or visual difference.

### Focus visualization

Three-part visualization (all parts required): the canvas focus box (layer above), the grid-row outline — pushed via the tree-grid `grid` service's `setFocused(id)` (the push direction follows the existing downward edge; the grid marks `sg-grid-row--focused`, 2 px inset outline in `--sg-focus-stroke`, and scrolls the row into its own viewport) — and the grid pane's `:focus-visible` ring. The canvas box alone does not satisfy this contract. DOM focus entering the mirror (including the row-0 tabindex fallback) renders the full visualization without a store set; it clears when DOM focus leaves before any effective placement, and persists after one. Every effective focus move scrolls the focused row fully into view through the public view service (clamped, emits `view/scrolled`) — a placement already fully visible scrolls nothing.

### Focus follows the pointer

A primary-button press on a grid row, or on a bar whose hit kind is `"bar"` (the body only — a press on a resize handle or the progress strip is the start of an edit gesture and does NOT move focus), places the roving focus on that task (and resets the keyboard anchor); non-primary presses (right, middle) never move focus. Pointer-driven placements are ordinary effective placements (store set + visualization).

### Announcements

Only keyboard-driven changes speak: keyboard selection chords (`selectionCount`, after an effective change only), expand/collapse (`rowExpanded`/`rowCollapsed`), keyboard-initiated inline-edit commits (`editCommitted` — the commit is detected through the `data` plugin's `tasks` store subscription, paired with the plugin's own edit-start bookkeeping so pointer commits stay silent), sort cycle steps (`sortChanged` — driven by the tree-grid `grid` store's sort field), keyboard zoom (`zoomChanged`). Pointer-made selection changes are not announced.

### Default bindings (contributed to `keys/bindings`, all replaceable)

| Chord | Action | Condition |
|---|---|---|
| `ArrowDown` / `ArrowUp` | move row focus (described: "Move focus down/up") | always |
| `+` / `-` | expand / collapse the focused summary row by dispatching `view/rowToggle { id, expanded }` (tree-grid's command), announcing the result | always (shadowed by zoom while `zoomKeys` is on) |
| `Home` / `End` | focus first / last reachable row (scrolls into view) | always |
| `ArrowRight` | expand a collapsed expandable row (via `view/rowToggle`, as `+` does); else move to first child of an expanded row; else no-op | always |
| `ArrowLeft` | collapse an expanded row (via `view/rowToggle`, as `-` does); else move to the parent row; no-op on a top-level leaf | always |
| `Enter` | dispatch `view/editStart { id }` for the focused row (no-op on the tree-grid side when it cannot edit) | always |
| `Shift+ArrowDown` / `Shift+ArrowUp` | move focus one row without the `syncSelection` replacement; set the selection to the inclusive visible-row range between the keyboard anchor and the new focus (Shift-click semantics) | `when`: the late-resolved `SelectionService` reports `mode() === "multi"` (unresolved service → inactive, keystroke falls through) |
| `Ctrl+Space` | toggle the focused row's selection membership | `when`: same rule as the Shift chords |
| `?` | toggle the shortcut-help dialog | only contributed when `shortcutHelp` is on |
| `Ctrl+Alt+S` | build / remove the summary table | only contributed when `summaryTable` is on |
| `Escape` | close the summary table | contributed with `when`: table open (falls through otherwise) |
| `+` / `-` (zoom) | one zoom step finer / coarser | only contributed when `zoomKeys` is on; contributed after the expand/collapse pair, so last-wins shadows them (outline toggling stays on ArrowRight/ArrowLeft) |

Keyboard anchor: the row of the last non-Shift focus placement; plugin-local, reset by every plain arrow move, every `focus()` call, and every selection change the plugin did not itself cause — foreign changes observed through the same optional/late `SelectionService.state` subscription that drives the `aria-selected` mirroring; the keyboard anchor may diverge from the pointer anchor after mixed sequences, and that divergence is accepted. The multi-selection chords operate exclusively through the public `SelectionService` (resolved late and optionally — see Dependencies) and announce `selectionCount` after each effective change. `syncSelection` (default `true`): every plain focus move calls `SelectionService.select([id])` when the service is composed; `false` — or an absent service — moves only the focus.

The keyboard move/resize/progress chords themselves are the interaction plugin's contributions (interaction.md §5); their summary-task no-op and announcements ride the focus channel here.

### Shortcut-help dialog (`shortcutHelp`, opt-in)

`?` toggles a `role="dialog" aria-modal="true"` dialog mounted in the chart root while open, focus taken on open and restored on close. Content: one line per canonical chord, the last (winning) contribution's `key` + `description`; undescribed bindings unlisted; a described binding shadowed by an undescribed one is not resurrected. Chrome text via `shortcutHelpTitle` / `shortcutHelpClose`. While open, the narrow swallow rule: modifier-carrying chords pass to the browser un-prevented (page zoom, find-in-page); scroll keys scroll the dialog natively and reach no binding; `Escape` and `?` close (prevented); `Tab` / `Shift+Tab` cycle a dialog-internal focus ring (panel ↔ close button, wrapping); every other plain key is swallowed. Close button ≥ 24×24 px; text contrast ≥ 4.5:1; no animation.

### Summary table (`summaryTable`, opt-in)

`Ctrl+Alt+S` builds — on demand only — a visually hidden `.sg-a11y-summary` holding one `<table>`: caption `summaryTitle`, four `scope="col"` headers (`summaryHeader`), one row per task with name, ISO start day, ISO end day (UTC), whole-percent progress (empty cell when absent). Whole store in tree order, collapsed branches included, capped at the first 1000 tasks (caption states truncation via `shown`/`total`). DOM focus moves into the table; `Ctrl+Alt+S` again or `Escape` removes it and restores focus.

### Keyboard zoom (`zoomKeys`, opt-in)

`+` / `-` step the zoom one level finer / coarser and announce the level then in force (`zoomChanged`, level id from the view plugin's `timeline.zoomLevel` store). The chords are the plain keys, never `Ctrl+±` (the browser's page zoom is never claimed). The chords dispatch the view plugin's `timeline/zoomIn` / `timeline/zoomOut` commands (Layer 2 — a strictly downward edge, no interaction-plugin dependency). Design note: the keyboard steps walk the full composed zoom ladder; a `zoomControls.levels` subset configured on the interaction plugin restricts only the toolbar, not these chords.

## Messages

`A11yMessages` — 12 keys, all builders. Dates render as `new Date(t).toISOString().slice(0, 10)` (UTC); the period separator is U+2013 EN DASH with one space each side; segments join with `", "`. Dates stay ISO regardless of locale (hosts localize inside their own builders).

| Key | Signature | Default |
|---|---|---|
| `rowText` | `(parts: { name; start; end; progress? }) => string` | `"<name>, <start> – <end>"`, plus `", <round(progress × 100)>%"` when `progress` present |
| `rowExpanded` | `(name: string \| undefined) => string` | `"<name>, expanded"`; `"expanded"` without a name |
| `rowCollapsed` | `(name: string \| undefined) => string` | `"<name>, collapsed"`; `"collapsed"` without a name |
| `selectionCount` | `(count: number) => string` | `"<count> selected"` (plain decimal) |
| `sortChanged` | `(input: { header: string; direction: "ascending" \| "descending" \| null }) => string` | `"<header>, sorted ascending"` / `"<header>, sorted descending"` / `"<header>, sort off"` |
| `editCommitted` | `(name: string \| undefined) => string` | `"<name>, updated"`; `"updated"` without a name |
| `rowDependencies` | `(parts: { predecessors: string[]; successors: string[] }) => string` | `"Depends on: <names>. Blocks: <names>"` — names joined `", "`, segments joined `". "`, empty segments left out |
| `shortcutHelpTitle` | `() => string` | `"Keyboard shortcuts"` |
| `shortcutHelpClose` | `() => string` | `"Close"` |
| `zoomChanged` | `(level: string) => string` | `"Zoom: <level>"` |
| `summaryTitle` | `(parts: { total: number; shown: number }) => string` | `"Gantt chart summary, <total> tasks"`; `"Gantt chart summary, first <shown> of <total> tasks"` when capped |
| `summaryHeader` | `(column: "name" \| "start" \| "end" \| "progress") => string` | `"Name"` / `"Start"` / `"End"` / `"Progress"` |

Deliberately not in the catalog: the treegrid's accessible name (that is `label`); ARIA state attributes.

## Dependencies

hard: `data` (L1 — row text, links, summary table), `view` (L2 — scroll-into-view, `view/scrolled`, zoom level/commands, theme token), `rows` + `grid` (L3, tree-grid — row model, reachable sequence, `setFocused`, sort state, the `view/editStart` and `view/rowToggle` commands), `task-bars` (L4 — focus-box geometry). optional: `selection` (interaction — `syncSelection`, the multi chords, `aria-multiselectable`; see the degradation rules below).

Layer verification (architecture ch. 5): `data`/`view`/`rows`/`task-bars` are strictly lower layers — all hard edges point strictly downward. `selection` is provided by the interaction plugin, the SAME Layer 5, so per ch. 5's "same-layer references are optional-only" rule (no exception granted) it is declared **optional** and resolved late — a `ctx.useOptional("stargantt.selection")` lookup at use time, never at `setup()` (the interaction plugin may start after this one). The edge is one-way and acyclic: interaction's reverse edge to `stargantt.focus` stays optional and late-resolved as well.

**Degradation semantics without `stargantt.selection` (normative).** In a composition without the interaction plugin (or any provider of `stargantt.selection`):

- The multi-selection chords (`Shift+ArrowDown` / `Shift+ArrowUp` / `Ctrl+Space`) are still contributed but their `when()` reports inactive while the service is unresolved, so the keystrokes fall through to other contributions.
- `syncSelection` has nothing to sync: plain focus moves move only the focus, exactly as with `syncSelection: false`. No error is reported.
- `aria-multiselectable` is never set on the treegrid (the attribute follows the resolved service's `mode()`, and an unresolved service reports nothing).
- `aria-selected` is never set on mirror rows (the mirroring rides the selection store subscription, and there is no store to subscribe).
- `selectionCount` announcements never fire (they are produced only by the chords above).
- Everything else — focus navigation and the roving tabindex, mirror generation, the focus visualization, `announce()`, expand/collapse, Enter-to-edit, help dialog, summary table, keyboard zoom — works standalone, unchanged.

## Third-party surface

- **Consumable services:** `stargantt.focus` (`FocusService`) — focused-row store, `focus(id)`, and `announce()` for aria-live messages.
- **Contributable extension points (with merge strategy):** `keys/bindings` (collect, last-wins) — third parties register their own bindings and may override any official chord; the dispatch rules of §Extension points apply to every contribution equally.
- **Subscribable events:** none of its own; focus is observed via store subscription.
- **Reserved namespaces (documentation convention only):** the `keys/` extension-point namespace, the `stargantt.focus` service ID, and the `renderer/layers` order key claimed above. Not enforced in core.
- **Hardening:** contributed `run`/`when` and host message builders are foreign code — guarded by the core error boundary (`core/pluginError`, dispatch continues / default answers the call). The mirror never exposes internal nodes as API; ids are unique per document so multiple instances coexist.
